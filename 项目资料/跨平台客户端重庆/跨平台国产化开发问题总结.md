> 基于 MICS_Client 项目代码及 Git 提交记录整理

## 一、最严重问题：麒麟 V10 UKUI 环境下客户端反复崩溃

### 1.1 问题现象

客户端在麒麟 V10 SP1 UKUI 桌面环境中运行一段时间后反复崩溃，呈现 **崩溃 → 自动重启 → 再次崩溃** 的恶性循环，间隔 30 秒 ~ 4 分钟不等，严重影响生产可用性。

**关联提交（4轮修复）：**
- `f387c531` — 第一轮修复
- `87d14ece` — 第一轮修复（cherry-pick）
- `adbd0a21` — 第二轮修复
- `d5139155` — 最终修复（611行新增，235行删除，涉及17个文件）

### 1.2 崩溃链分析

```
网络异常/服务端无响应 → API 返回 null
  → LevelColors 空集合 → 索引越界
  → AlarmLine1/2/3 为 null → Avalonia 绑定报错
  → 大量 Binding Error 在 .NET ThreadPool 堆积
  → JIT doublemapper 内存区域空指针 → SIGSEGV 崩溃
```

**根因对比：**
- **Windows WPF**：对 null 绑定静默容错，不会抛出异常
- **Linux Avalonia**：对 null 绑定 / 集合索引越界会抛出异常，大量异常在 ThreadPool 累积，最终触发 .NET Runtime 的 `memfd:doublemapper` 段错误

### 1.3 解决方案 — 四层防御体系

| 层级 | 防御措施 | 解决的问题 |
|------|---------|-----------|
| **Layer 1 — 数据层** | `LevelColors` 预填充 10 个默认颜色；`AlarmLine1/2/3` 预初始化为空对象；`ProcessAlarmColor` 加 try-catch + 默认颜色；`BrushCache` 对空字符串做守卫 | 从源头杜绝 null 绑定和索引越界 |
| **Layer 2 — 绑定层** | AXAML 中 `LevelColors[0]~[4]` 统一加 `FallbackValue=Transparent`；所有属性加 null 守卫 | 即使数据为 null，UI 也不抛异常 |
| **Layer 3 — 运行时** | `DOTNET_LinuxDoubleMapping=0` 禁用 doublemapper；`GCHeapHardLimit=8GB` 限制堆大小；`PublishReadyToRun=true` 预编译；`TieredPGO=true` | 减少 JIT 双映射内存区域和崩溃概率 |
| **Layer 4 — 生命周期** | 所有后台任务改用 `CancellationToken`；`_disposed` 守卫防止释放后访问 | 防止页面切换后后台任务操作已释放资源 |

### 1.4 关键代码

```csharp
// Program.cs — 运行时防护
Environment.SetEnvironmentVariable("DOTNET_LinuxDoubleMapping", "0");
Environment.SetEnvironmentVariable("DOTNET_GCHeapHardLimit", "0x200000000"); // 8GB

// AlarmBarViewModel — 数据预初始化（构造函数中）
for (int i = 0; i < 10; i++)
    LevelColors.Add(SolidColorBrush.Parse("#CCCCCC")); // 默认颜色

AlarmLine1 = CreateEmptyAlarmInfo(); // 非 null，避免绑定报错
AlarmLine2 = CreateEmptyAlarmInfo();
AlarmLine3 = CreateEmptyAlarmInfo();

// BrushCache — 防御性颜色解析
public static IBrush GetBrush(string colorString)
{
    if (string.IsNullOrWhiteSpace(colorString)) return Brushes.Gray;
    return _cache.GetOrAdd(colorString, key =>
    {
        try { return SolidColorBrush.Parse(key); }
        catch { return Brushes.Gray; }
    });
}
```

## 二、CEF 浏览器在国产化系统下的问题

### 2.1 CEF 进程频繁崩溃 / H5 页面白屏

**问题：** 麒麟 V10 显卡驱动兼容性差，CEF 有窗口渲染模式（Windowed）在 Linux 下崩溃。

**解决：** 启用离屏渲染（Windowless）+ 禁用 GPU 加速

```csharp
if (OperatingSystem.IsLinux())
{
    cefsetting.WindowlessRenderingEnabled = true;  // 离屏渲染
    cefFlags.Add("disable-seccomp-filter-sandbox", "true");
    cefFlags.Add("disable-gpu", "true");           // 纯 CPU 渲染
}
```

**关联提交：** `7d98a4ab`、`c95d1d9b`

### 2.2 麒麟 V10 + UKUI 下 Win+D 返回桌面后 CEF 页面不刷新

**问题：** 在麒麟 V10 UKUI 桌面环境下，操作员使用 Win+D 快捷键返回桌面后再切换回客户端，CEF 加载的线路图等 H5 页面不再刷新。

**解决：** 在 `CefView.axaml.cs` 中增加焦点恢复检测，窗口重新获得焦点时检测 CEF 浏览器状态并触发页面重载。

**关联提交：** `69a987fe`

### 2.3 Linux 下控件遮挡和输入法焦点问题

**问题：** CEF 有窗口模式在 Linux 下，CEF 的 X11 窗口会遮挡 Avalonia 原生控件，且中文输入法焦点异常。

**解决：** 切换到离屏渲染模式（Windowless），CEF 内容被渲染到 Avalonia 的绘图表面中，不再有独立 X11 窗口。

### 2.4 CEF 内存泄露与 WebSocket 线程泄露

**问题：** 客户端长时间运行后，CEF 浏览器实例和 WebSocket 连接未被正确释放。

**解决：**
- `CefView` 延迟初始化，仅在首次加载 Web 内容时创建 CEF 实例
- `InspectorPanelViewModel` 增加 CancellationToken 取消无限循环任务
- `WaitingRequestResult` 临时 WebSocket 事件取消订阅

**关联提交：** `b9160e9f`、`40b8c124`

## 三、VLC/libvlc 在麒麟系统下的问题

### 3.1 libvlc PulseAudio 插件崩溃

**问题：** 麒麟 V10 UKUI 桌面系统下，libvlc 的 PulseAudio 音频插件导致客户端崩溃。

**解决：** 在 `AlarmAlertPlayer.cs` 中增加告警播放异常保护，捕获音频播放异常防止影响主流程；调整 LibVLC 初始化参数适配国产化音频环境。

**关联提交：** `36ae8b01`

### 3.2 播放一段时间后画面卡住

**问题：** RTSP 视频流播放一段时间后画面静止不动。

**解决：** 添加 `--clock-synchro=0` 禁用时钟同步

```csharp
private readonly static LibVLC _libVlc = new(
    "--network-caching=3000",
    "--avcodec-hw=none",       // 禁用硬件解码
    "--rtsp-tcp",              // RTSP over TCP
    "--clock-synchro=0",       // 解决画面卡住
    "--no-xlib"                // 禁用 X11 依赖
);
```

### 3.3 停止播放后视频画面残留

**问题：** 停止视频播放后，画面上仍残留最后一帧静止图像。

**解决：** 添加 `--no-xlib` 参数，强制 VLC 不依赖 X11 窗口系统，使用帧缓冲直接渲染。

**关联提交：** `f1fe96c1`

### 3.4 四分屏弹窗时 VLC 独立窗口弹出

**问题：** CCTV 四分屏弹窗时，偶尔弹出 VLC 独立播放窗口。

**解决：** 强制 VLC 不使用独立窗口输出，确保视频渲染在 Avalonia 控件内。

**关联提交：** `0a3e5d9c`、`64cce7c5`

## 五、跨平台系统级兼容问题

### 5.1 X11 截图像素错位

**问题：** 初版代码将 X11 `XGetImage` 返回的像素当作 3 字节 BGR 处理，实际是 4 字节 BGRA，导致截屏图片颜色偏移、画面错位。

```csharp
// 修复前（错误）
int srcIdx = y * ximage.bytes_per_line + x * 3;  // ❌ 像素偏移计算错误

// 修复后（正确）
int srcIdx = (y * ximage.bytes_per_line) + (x * 4);  // ✅ 按 4 字节 BGRA 步进
```

**关联提交：** `11214e45`（MicsClient.Linux.readme v5.0.0.2）

### 5.2 打印功能在 Linux 下不可用

**问题：** Linux 没有 Windows 的 Shell Verb 机制，无法调用系统默认程序打印。

**解决：** 实现完整的 IPP/CUPS 协议（使用 SharpIppNext 库），包括打印机发现、能力查询、作业提交。

| 维度 | Windows | Linux（麒麟 V10） |
|------|---------|------------------|
| 技术方案 | Shell Verb `print`/`printto` | IPP/CUPS 协议（SharpIppNext） |
| 打印机发现 | `PrinterSettings.InstalledPrinters` | `CUPSGetPrinters` IPP 请求 |
| 能力查询 | 仅基础有效性检查 | 完整查询：双面、彩色、支持格式、打印机状态 |
| 作业提交 | 操作系统默认 PDF 处理器 | 直接 IPP `PrintJob` 请求 |

**关联提交：** `2b227048`

### 5.3 deb 打包后文件路径错误

**问题：** 通过 deb 包安装到麒麟系统后，`AppDomain.CurrentDomain.BaseDirectory` 返回路径不正确，无法加载配置文件。

**解决：** 简化运行目录获取方式，统一使用可执行文件所在路径。

**关联提交：** `3529e6a8`、`7a3286ef`

### 5.4 组件加载顺序导致闪退

**问题：** CEF 尚未就绪时就尝试创建浏览器实例，在 Linux 下导致闪退（Windows 下因时序差异不易触发）。

**解决：** 两阶段初始化（闪屏前轻量级 → 闪屏后异步重型组件）+ CEF 延迟初始化。

**关联提交：** `cc979cff`

### 5.5 国产化系统时间格式转换异常

**问题：** BAS 时间表模块在国产化系统中时间格式转换出错。

**解决：** 修复 `BasTimeDao` 中的时间格式处理逻辑。

**关联提交：** `e0f0a61a`

### 5.6 配置工具在 Linux 下导入功能报错

**问题：** 配置工具在 Linux 下直接使用导入功能时报错。

**解决：** 升级 Avalonia 版本至 11.3.7，修复跨平台文件路径和编码兼容性问题。

**关联提交：** `17e171b4`、`33c06480`

### 5.7 单实例互斥锁跨平台差异

**问题：** Windows 使用 `Global\` 前缀的互斥锁名称，Linux 不支持。

```csharp
var lockName = OperatingSystem.IsWindows() 
    ? "Global\\MicsClient-SingleInstance" 
    : "MicsClient-SingleInstance";
```

### 5.8 Core Dump 配置（Linux 崩溃诊断）

```csharp
// 启用 .NET 崩溃 dump
AppContext.SetData("DOTNET_DbgEnableMiniDump", 1);
```

## 六、跨平台适配整体架构

```
        IPlatformNativeService（策略模式接口）
                   │
        ┌──────────┴──────────┐
        ▼                     ▼
 WindowsPlatformService   LinuxPlatformService
  • Win32 截屏              • X11 + Xinerama 截屏
  • Shell Verb 打印         • IPP/CUPS 打印
```

### 完整适配清单

| 适配项 | Windows | 麒麟 V10 |
|--------|---------|---------|
| UI 渲染 | Avalonia Direct2D/GPU | Avalonia Skia CPU（禁用 GPU） |
| Web 内容 | CEF Windowed | CEF Windowless + 禁 GPU |
| 截屏 | WinForms API | X11 P/Invoke + Xinerama |
| 打印 | Shell Verb | IPP/CUPS 协议 |
| 崩溃防护 | 不需要 | 四层防御体系 |
| 安装包 | 直接复制 | deb/rpm 包 |
| 字体 | 系统自带 | 内嵌 MiSans（22种变体） |
| Core Dump | Windows Error Reporting | prctl + MiniDump |
| 运行时优化 | 默认配置 | ReadyToRun + TieredPGO + GC限制 + 禁DoubleMapping |

## 七、关键经验总结

1. **Avalonia ≠ WPF**：Linux Avalonia 对 null 绑定不容错（WPF 静默容错），所有绑定数据必须预初始化，AXAML 必须加 `FallbackValue`
2. **GPU 加速要谨慎**：麒麟 V10 显卡驱动兼容性差，CEF 和 Avalonia 均需禁用 GPU，使用 CPU 软件渲染
3. **.NET on Linux 的 JIT 问题**：doublemapper 段错误是已知问题，需要通过 `DOTNET_LinuxDoubleMapping=0` + ReadyToRun 组合规避
4. **后台任务必须可取消**：7×24 运行环境下，页面切换后未取消的后台任务是崩溃的主要根源
5. **原生系统服务必须抽象**：截屏、打印、文件路径等必须通过策略模式抽象，不能直接调用平台 API
6. **CEF 启动时序敏感**：Linux 下组件初始化顺序比 Windows 更敏感，必须两阶段初始化 + 延迟加载
7. **PulseAudio 兼容**：麒麟 V10 的音频子系统与 Windows 不同，VLC 音频插件需要特殊处理
