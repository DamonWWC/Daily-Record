# MICS_Client 项目总结文档

> 生成日期：2026-06-08

---

## 一、项目概述

**MICS_Client** 是一个**城市轨道交通综合监控系统（MICS — Metro Integrated Control System）的客户端工作站软件**，面向地铁/城轨运营场景，为调度员和车站值班员提供统一的监控、报警、控制和运营管理界面。

项目支持跨平台运行，目标平台涵盖 **Windows** 和 **国产操作系统（银河麒麟 V10 SP1 UKUI）**。

## 三、技术方案与实现细节

### 3.1 依赖注入与服务容器

#### 框架：Microsoft.Extensions.DependencyInjection

采用**静态服务定位器模式**（Service Locator），通过 `ServiceManager.Services` / `ServiceManager.Locator` 实现全局服务注册与解析：

```csharp
ServiceManager.Services.AddSingleton<T>()      // 单例服务
ServiceManager.Services.AddTransient<T>()      // 瞬时 ViewModel
ServiceManager.Locator.GetRequiredService<T>() // 运行时解析
```

#### 两阶段初始化管线

| 阶段 | 方法 | 初始化内容 |
|------|------|-----------|
| **阶段一**（闪屏前） | `InitBaseComponents()` | 配置加载（`IConfiguration`、`MicsConfigurations`、`SessionConfiguration`）、NLog 日志、`LogArchiverService` |
| **阶段二**（闪屏后，异步） | `InitComplexComponents()` | YARP 反向代理、HTTP/WebSocket 客户端、`MicsWindowDispatcher`、`PlanService`、`NotificationService`、`AlarmAlertPlayer`、ViewModel 注入、CEF 初始化 |

### 3.3 内嵌反向代理（YARP）

客户端内嵌 **ASP.NET Core Kestrel 服务器**，运行于 `localhost:{ProxyPort}`（默认 15024），作为所有后端请求的统一出口：

```
Client → localhost:15024 → [YARP] → 后端服务器群（MICS-XDZ-1:15777 等）
                                ↓
                          LocalService 本地端点 (/ClientInternal/*)
```

#### 核心特性

| 特性 | 实现 |
|------|------|
| **多服务器故障转移** | CSV 定义的后端主机列表，配合健康检查（`ConsecutiveFailures` 策略） |
| **站点级路由** | `/{LocationName}/**` → 对应车站服务器 |
| **服务器级路由** | `/{ServerName}/**` → 特定服务器 |
| **兜底本地路由** | 未匹配请求 → 当前车站 |
| **请求头注入** | `ClientProxyHeaderTransform` 注入加密认证头（Console、OperatorId、Session、ProfileId、PlaceType、SHA256 Tracking） |
| **本地 API 端点** | `/ClientInternal/*` 通过 Minimal API 映射，实现 Web↔Native 桥接 |
| **Swagger/Knife4j** | 运行时内嵌 API 文档 |

#### 本地 API 桥接端点（LocalService）

| 端点 | 功能 |
|------|------|
| `POST /ClientInternal/changeLoc` | 切换监控车站 |
| `GET /ClientInternal/currLoc` | 查询当前车站 |
| `POST /ClientInternal/callmenu` | 导航到菜单/页面 |
| `POST /ClientInternal/popup` | 打开弹窗 |
| `POST /ClientInternal/inspectorPanel` | 打开设备监控面板 |
| `POST /ClientInternal/cctvDisplay` | 显示 CCTV 视频弹窗 |
| `POST /ClientInternal/tvWallPlay` | 电视墙显示 |
| `GET /ClientInternal/serverList` | 获取可用服务器列表 |
| Alert 系列端点 | 启动/停止/配置报警声音 |

### 3.4 WebSocket 双通道架构

#### A. 客户端 → 服务端（`MicsWebsocketClient`）

| 技术点 | 实现 |
|--------|------|
| **传输层** | `ClientWebSocket` |
| **重试策略** | **Polly** 线性退避，无限重试，1s→30s 最大延迟 |
| **流处理** | `System.IO.Pipelines` 零拷贝字节流处理 |
| **双序列化** | JSON（默认）或 **MessagePack**（高吞吐场景，如设备数据） |
| **生产者-消费者** | `Channel<WebSocketCommand>` 用于发送和接收 |
| **心跳** | 15 秒超时触发自动重连 |
| **注册方式** | `AddMicsWebsocketClient()` 扩展方法，支持可配置 Base URL 和动态请求头 |

#### B. 服务端 → 内嵌页面（`LocalWebSocketService`）

| 技术点 | 实现 |
|--------|------|
| **地址** | `/ClientInternal/notification` |
| **模型** | 发布/订阅，支持主题订阅（`ALERT_SET`、`LOCATION_CHANGED`、`MENU_CHANGED`） |
| **心跳** | 每 2 秒发送 |
| **并发管理** | `ConcurrentSet<WebSocketSubscriber>` |
| **桥接** | 订阅 `WeakReferenceMessenger` 消息并转发为 WS 命令 |

#### WebSocket 命令协议

```json
{
  "command": "HEART_BEAT | ALARM | DATA_POINT | EVENT | PLAN | ...",
  "data": {},
  "message": ""
}
```

约 20 种命令类型：`ALARM`、`ALARM_SYNC`、`DATA_POINT`、`DEVICE`、`EVENT`、`SET_EVENT_FILTER`、`PLAN`、`PLAN_ACTION`、`NOTIFICATION_MESSAGE`、`FULL_SYNC`、`STA_SYNC` 等。

#### WebSocket 服务端基类（`WebSocketServiceBase`）

所有服务端 WebSocket 服务（Alarm、Event、DeviceData、PA、PIS、Plan、Notification、BAS、SystemManager）共享抽象基类：

- 维护 `ConcurrentSet<WebSocketSubscriber>` 连接跟踪
- 命令分发通过 `ConcurrentDictionary<string, Func<WebSocketSubscriber, WebSocketCommand, Task>>` 实现
- 内建 2 秒心跳，自动清除死连接
- 子类实现：`InitOtherRecivedCommands()`、`NewConnectAction()`、`RemoveConnectAction()`

### 3.5 ICE 中间件（核心通信层）

#### 技术：ZeroC ICE（非 gRPC）

系统使用 **ZeroC ICE**（Internet Communications Engine）作为 RPC 中间件，通过生成的代理类（`IAlarmOperatorPrxHelper`、`IDataPointAccessorPrxHelper` 等）和 `Ice.Communicator` 实现高性能远程调用。

#### 架构分层

```
┌───────────────────────────────────────┐
│   IIceConnection (接口层)              │  ← 纯接口 + 数据模型
│   IAlarmInterface, IDataInterface...  │
├───────────────────────────────────────┤
│   IceConnection.Cd (成都项目实现)      │  ← 项目特定的 ICE 实现
│   IceConnection.Generic (通用实现)     │  ← 通用 ICE 实现（已注释）
├───────────────────────────────────────┤
│   IceConnectionFactory (工厂模式)      │  ← DI 注册 + 实现选择
└───────────────────────────────────────┘
```

#### 连接基类（`IceConnectionBase`）

| 技术点 | 实现 |
|--------|------|
| **状态机** | `DisConnect → Connecting → Connected`，使用 `Interlocked.Exchange` 保证线程安全 |
| **重试策略** | **Polly** 线性退避，无限重试，最大延迟 5 分钟，起始 1 秒 |
| **网络探测** | `GetLocalEndPointHost()` 测试哪个本地网卡可达目标后再绑定 |
| **上下文传递** | 每次 ICE 调用携带 `MICS-GUID` 上下文头用于链路追踪 |

#### ICE 接口实现模式（以 AlarmInterface 为例）

1. **构造函数 DI**：注入 `ISystemNameInterface`、`ILogger`、`IConfiguration`
2. **服务发现**：调用 `systemName.QueryServiceConfigExAsync()` 动态发现 Agent 的 Host/Port
3. **多主机故障转移**：遍历逗号分隔的主机列表，逐个尝试直到连接成功
4. **代理创建**：`ic.stringToProxy(str)` → `IAlarmOperatorPrxHelper.checkedCast(p)`
5. **回调注册**：创建本地 `ObjectAdapter` 在动态端口上，向远端注册回调 Servant
6. **心跳循环**：每 3 秒 `checkCallbackAliveAsync`，失败时断开并重新注册
7. **Channel 数据流**：接收到的数据推入 `System.Threading.Channels.Channel<T>` 解耦消费

#### 关键 ICE 接口清单

| 接口 | 功能 | 数据流模式 |
|------|------|-----------|
| `ISystemNameInterface` | 服务发现、Agent 查找、数据库配置 | 请求/响应 |
| `IAlarmInterface` | 报警确认/关闭/查询、雪崩控制 | 回调 Channel → `ChannelReader<AlarmUnitList>` |
| `IDataInterface` | 点位读/写/锁定/超驰/禁止/标记 | 回调 Channel → `ChannelReader<List<DataPoint>>` |
| `IEventInterface` | 事件生成/查询 | 回调 Channel → `ChannelReader<List<EventData>>` |
| `INotifyInterface` | 跨站点通知发布/订阅 | 请求/响应 |
| `IPaInterface` | 公共广播系统 | 回调 Channel |
| `IBasInterface` | 楼宇自控系统 | 回调 Channel |
| `IPlanInterface` | 应急预案管理 | 回调 Channel |
| `IRightInterface` | 权限与权限管理 | 请求/响应 |
| `ISigInterface` | 信号系统（仅 OCC） | 回调 Channel |

| 数据库 | 说明 |
|--------|------|

| Oracle | 企业级数据库 |

#### Facade 模式（`IDAFacade` / `DAFacade`）

- 抽象基类封装 Dapper 操作，提供统一 API
- 同步和异步方法：`Query<T>`、`QueryFirst<T>`、`Delete`、`GetPageList<T>`、`ExecuteNonQuery`、`ExecuteScalar`、`ExecuteReader`
- 每种数据库类型有具体的 Facade 实现（如 `SQLServerDAFacade`、`OracleDAFacade`），处理连接创建、参数前缀、分页 SQL 语法等差异

#### BaseDAO — 连接管理

| 技术点 | 实现 |
|--------|------|
| **多数据库故障转移** | 读取 `MicsConfig:DbConfig` 列表，按 `OrderNo` 顺序尝试连接 |
| **PreferDB 枚举** | `Current`（当前库）、`History`（历史库）、`NOCC`（NOCC 库） |
| **静态连接状态缓存** | `ConcurrentDictionary<string, (bool Success, DateTime Time)>` 跟踪每个连接串的最后已知状态 |
| **自动重试定时器** | 静态 `Timer` 每 5 秒后台重试失败的连接 |
| **线程安全** | `lock(Locker)` 保护初始化；`ConnStatus` 状态机防止双重初始化 |
| **字段映射** | `DefaultTypeMap.MatchNamesWithUnderscores = true` 支持蛇形命名到驼峰命名的映射 |
| **Repository 抽象** | `IRepository` / `RepositoryBase` + `DbSession` 包装器，支持外部会话绑定实现事务共享 |

### 3.8 H5/Web 混合桥接机制

#### 菜单导航模型（`MenuInfo.Type`）

| Type | 含义 |
|------|------|
| 0 | 父级菜单（容器） |
| 1 | 打开 SCADA / 组态页面 |
| 2 | 打开原生 Avalonia 管理器 |
| 3 | 打开 H5（Web）管理器 |
| 4 | 打开外部页面 |

#### 通信流向

```
┌──────────────┐                         ┌──────────────┐
│  Native UI   │  ── WeakReferenceMessenger ──→  │  LocalWS     │
│  (Avalonia)  │                         │  Service     │
│              │  ←── HTTP POST /ClientInternal/* ──  │  (H5 Bridge) │
└──────────────┘                         └──────┬───────┘
                                                │ WebSocket
                                         ┌──────▼───────┐
                                         │  H5/CEF 页面  │
                                         └──────────────┘
```

- **Native → Web**：通过 `LocalWebSocketService` 推送命令（`LOCATION_CHANGED`、`MENU_CHANGED`、`ALERT_SET`）
- **Web → Native**：通过 HTTP POST 到本地 ASP.NET Core 端点（`/callmenu` 等），携带加密头
- **请求验证**：`RequestValidator` 中间件校验 Body+ConsoleName 的 SHA256 哈希与 Tracking ID 头
- **会话安全**：请求头携带 DES 加密的 Session ID、Profile ID、Operator ID；操作员名称使用 Base64URL 编码

#### 浏览器模式（WASM）

`MicsClient.Pages.Browser` 通过 `StartBrowserAppAsync("out")` 将页面编译为 WebAssembly。页面通过 URL 查询参数路由（`?page=histAlarm`）。在浏览器模式下，`ClientCommunicator` 从 `WeakReferenceMessenger` 切换为 HTTP 调用本地桌面客户端。

### 3.10 安全模型

| 安全措施 | 实现方式 |
|---------|---------|
| **DES 加密** | 敏感请求头（OperatorId、Session、ProfileId）加密传输 |
| **Base64URL 编码** | 控制台名称和操作员名称编码 |
| **SHA256 请求追踪** | Body 完整性校验 |
| **单实例互斥锁** | `Global\MicsClient-SingleInstance` 防止多开 |
| **会话管理** | 登录 → 保活（5 秒轮询 `/right/keepAlive`）→ 注销 生命周期 |
| **角色权限** | Profile Group 匹配用于预案确认；静态+动态权限检查 |
| **请求校验** | `RequestValidator` 中间件验证 H5 桥接请求完整性 |

### 3.11 多屏窗口管理

- 管理 `ConcurrentSet<MicsHostWindow>` 基础窗口和弹窗

- **快捷键**：Ctrl+Shift+I → 打开监控面板输入对话框

#### Linux 运行时加固


### 3.15 报警数据流（端到端）

```
ICE AlarmAgent ──callback──→ AlarmInterface.Channel
    → AlarmService (await foreach 读取 Channel)
    → 更新 ConcurrentDictionary<int, ConcurrentSet<AlarmUnit>> (按 LocationId 分组)
    → 推送至 sendChannels (ConcurrentSet<Channel<List<AlarmUnit>>>)
    → AlarmWebSocket 从其 Channel 读取
    → 按订阅者偏好 + 范围过滤器筛选
    → WebSocket 推送至客户端
```

- **跨站路由**：本地报警直走 ICE；远端车站报警通过 YARP 代理 `IMicsHttpClient.PostAsync($"/{loc}/alarm/confirm")`
- **缓存**：每站内存报警集；显示配置每 60 秒从数据库刷新；范围过滤器按操作员 ID 缓存
- **线程模型**：多个 `Task.Run` / `Task.Factory.StartNew(LongRunning)` 后台循环处理报警、显示轮询、配置刷新

## 七、项目特点总结

### 7.1 行业属性强

这是一个典型的**城市轨道交通 ISCS（综合监控系统）** 客户端，深度对接 BAS（楼宇自控）、CCTV（视频监控）、PA（公共广播）、PIS（乘客信息）、SIG（信号系统）、SOE（事件顺序记录）等多个地铁子系统，为运营人员提供一站式的监控与操控平台。

### 7.2 跨平台要求高

需要同时运行在 Windows 和国产操作系统（银河麒麟 V10 SP1 UKUI）上，采用 Avalonia UI 实现 UI 跨平台渲染，并针对麒麟系统的 `memfd:doublemapper` 段错误问题构建了**四层防御体系**（数据层 → 绑定层 → 运行时 → 生命周期）。

### 7.3 高可靠性设计

- ICE 通信冗余（主备自动切换）
- AB 网双网环境兼容
- 双屏模式支持（左右屏状态同步）
- 冗余切换与重连机制
- 长时间运行稳定性保障（GC 堆限制、ReadyToRun 预编译）

### 7.4 模块化架构

每个子系统独立为 `Server` + `Pages` 模块对，遵循**面向接口设计**原则，便于团队协作和功能迭代。共享库（SharedLib）抽取公共模型与接口，避免重复代码。

### 7.5 H5 混合渲染

通过 CEF（Chromium Embedded Framework）嵌入浏览器承载组态画面和 H5 页面，实现**原生 + Web 混合 UI**。组态资源统一从本站服务加载，数据由对应车站提供。

### 7.6 持续迭代

项目处于活跃开发状态，近期以缺陷修复和性能优化为主，同时持续扩展新功能（如双控、点位管理、SIG 隧道阻塞、全局通知等）。
