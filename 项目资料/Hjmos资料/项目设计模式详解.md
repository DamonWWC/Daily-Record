## 1. 观察者模式 / 发布-订阅（Observer / Publish-Subscribe）

### 1.1 概念

**观察者模式**定义对象间的一对多依赖关系：当一个对象（主题/发布者）的状态发生变化时，所有依赖它的对象（观察者/订阅者）都会收到通知并自动更新。

**发布-订阅**是观察者模式的变体，引入了一个中间事件通道（Event Bus），发布者和订阅者完全解耦——双方不需要知道对方的存在。

```
                    经典观察者                          发布-订阅
               ┌──────────────┐              ┌──────────────────────┐
  Subject ────►│  Observer A  │    Publisher │    Event Channel     │ Subscriber A
               │  Observer B  │       ──────►│  (EventBus/Topic)    │◄────────────
               │  Observer C  │              └──────────────────────┘ Subscriber B
               └──────────────┘                      ▲                 Subscriber C
    Subject 持有 Observer 引用              Publisher │ Subscriber 互不感知
```

### 1.2 项目中的实现：EventBus

项目基于 Prism 的 `PubSubEvent<T>` 封装了自己的 `EventBus`，用枚举值作为事件键，实现了跨模块的发布-订阅通信。

**核心实现**（`Nuget\Hjmos\Common\EventBus\EventBus.cs`）：

```csharp
public class EventBus : IEventBus
{
    // 事件注册表：枚举键 → 事件实例
    private readonly Dictionary<Enum, EventBase> events = new Dictionary<Enum, EventBase>();
    
    // 捕获 UI 线程的同步上下文，确保订阅者可回到 UI 线程
    private readonly SynchronizationContext syncContext = SynchronizationContext.Current;

    /// <summary>
    /// 获取或创建带载荷的事件
    /// </summary>
    public PubSubEvent<T> GetEvent<T>(Enum key)
    {
        lock (events)  // 线程安全：只锁字典访问
        {
            if (!events.TryGetValue(key, out EventBase existingEvent))
            {
                PubSubEvent<T> newEvent = new PubSubEvent<T>
                {
                    SynchronizationContext = syncContext  // 注入 UI 线程上下文
                };
                events[key] = newEvent;
                return newEvent;
            }
            return (PubSubEvent<T>)existingEvent;
        }
    }

    /// <summary>
    /// 获取或创建无载荷的事件
    /// </summary>
    public PubSubEvent GetEvent(Enum key)
    {
        lock (events)
        {
            if (!events.TryGetValue(key, out EventBase existingEvent))
            {
                PubSubEvent newEvent = new PubSubEvent
                {
                    SynchronizationContext = syncContext
                };
                events[key] = newEvent;
                return newEvent;
            }
            return (PubSubEvent)existingEvent;
        }
    }
}
```

**事件键定义**（`Nuget\Hjmos\Common\Events\CommonEvents.cs`）：

### 1.4 线程安全设计

| 关注点 | 实现方式 |
|--------|----------|
| 字典并发访问 | `lock(events)` 保护 get-or-create，粒度小，不影响 Publish/Subscribe 性能 |
| UI 线程回调 | 构造时捕获 `SynchronizationContext.Current`，注入到每个 `PubSubEvent` |
| 内存泄漏防护 | 订阅时传 `keepSubscriberReferenceAlive: false`，使用弱引用 |

### 1.5 优缺点

**优点：**
- 模块间零耦合：`IntelligentLinkage` 和 `StationEmergencyCommand` 互不引用
- 动态扩展：任何模块可随时订阅/取消订阅，无需修改发布者
- 线程安全：自动支持 UI 线程回调和后台线程处理

**缺点：**
- 事件流转不透明：难以追踪一个事件的完整传播链路
- 弱引用可能导致意外 GC：订阅者如果无其他引用可能被回收
- 无载荷事件缺少上下文：收到 `ReflashToken` 通知但不知道新 Token 值

## 2. 策略模式（Strategy）

### 2.1 概念

**策略模式**定义一组算法（策略），将每个算法封装为独立的类，使它们可以互相替换。客户端通过接口调用策略，不关心具体实现。策略的选择可以在运行时决定。

```
          ┌─────────────────┐
          │   Context        │
          │  (使用策略的类)   │
          │                  │
          │  strategy.Do()   │
          └────────┬─────────┘
                   │ uses
          ┌────────▼─────────┐
          │ <<interface>>    │
          │   IStrategy      │
          │  + Do()          │
          └────────┬─────────┘
                   │ implements
       ┌───────────┼───────────┐
       │           │           │
┌──────▼────┐ ┌────▼─────┐ ┌──▼────────┐
│StrategyA  │ │StrategyB │ │StrategyC  │
│(ISCS代理) │ │(RTSP直连)│ │(ONVIF直连)│
└───────────┘ └──────────┘ └───────────┘
```

### 2.2 项目中的实现：IVideoService 三种视频播放策略

项目需要通过三种不同的技术方案播放监控视频，通过配置在运行时切换策略。

**策略接口**（`src\Hjmos.Service\Media\IVideoService.cs`）：

```csharp
public interface IVideoService
{
    // 播放视频
    Task<VideoPlayResultInfo> PlayVideo(VideoPlayInfo videoPlayInfo);
    // 停止播放
    Task<ResultInfo> StopVideo(string sessionId);
    // 保活
    Task<ResultInfo> KeepAlive(string sessionId);

    // 云台控制（PTZ）
    Task<ResultInfo> ToLeft(string deviceCode);
    Task<ResultInfo> ToRight(string deviceCode);
    Task<ResultInfo> ToUp(string deviceCode);
    Task<ResultInfo> ToDown(string deviceCode);
    Task<ResultInfo> ToZoomIn(string deviceCode);
    Task<ResultInfo> ToZoomOut(string deviceCode);

    // 目录查询
    Task<List<VideoCatalogNode>> GetHjmosVideoCatalog(...);
    // ... 共 27 个方法
}
```

**策略 A — ISCS 代理模式**（`VideoService`，配置值 `"1"`）：

```csharp
// 通过综合监控系统（ISCS）的媒体代理播放视频
public class VideoService : IVideoService, IDisposable
{
    public async Task<VideoPlayResultInfo> PlayVideo(VideoPlayInfo videoPlayInfo)
    {
        return await PlayVideoByIscs();
        // 内部流程：
        // 1. 调用 ISCS API 获取摄像头代理配置（register → open → close → heartbeat）
        // 2. 通过 ISCS 媒体代理建立播放会话
        // 3. TaskCompletionSource 等待第一个成功的播放结果
    }

    // PTZ 通过 ISCS API 控制
    public Task<ResultInfo> ToLeft(string deviceCode)
        => IscsCameraApi.Left(deviceCode);
}
```

**策略 B — RTSP 直连模式**（`VideoService2`，配置值 `"0"`/默认）：

```csharp
// 继承 VideoService 复用目录查询等方法，重写播放和 PTZ 逻辑
public class VideoService2 : VideoService
{
    private readonly ConcurrentDictionary<string, string> CameraDic = new();

    public override async Task<VideoPlayResultInfo> PlayVideo(VideoPlayInfo videoPlayInfo)
    {
        // 直接调用后端获取 RTSP 地址，绕过 ISCS 代理
        var result = await RestApi.RequestAsync<RestfulResponse<Dictionary<string, string>>>(
            url: "/hjmos-mediacenter-admin/camera/getCctvRtsp", ...);

        // 分配会话 ID，存储映射关系
        foreach (var camera in result.Data)
        {
            var sessionId = Guid.NewGuid().ToString();
            CameraDic[sessionId] = camera.Key;
        }
    }

    // PTZ 通过宇视 SDK 直接控制摄像头
    public override Task<ResultInfo> ToLeft(string deviceCode)
    {
        UniviewHelper.PanAction(deviceCode, MW_PTZ_CMD_E.MW_PTZ_PANLEFT, true);
        Task.Delay(1000).ContinueWith(_ =>
            UniviewHelper.PanAction(deviceCode, MW_PTZ_CMD_E.MW_PTZ_PANLEFT, false));
        return Task.FromResult(new ResultInfo(true));
    }

    // 保活：使用 Rx 的 Buffer 操作符，每 10 秒批量处理
    private readonly Subject<string> _sessionSubject = new();
    public VideoService2()
    {
        _sessionSubject
            .Buffer(TimeSpan.FromSeconds(10))
            .Select(x => x.Distinct())
            .Subscribe(KeepAliveBatch);
    }
}
```

**策略 C — ONVIF 直连模式**（`VideoService3`，配置值 `"2"`）：

```csharp
// 继承 VideoService2，重写 PlayVideo 使用 ONVIF 协议直接从摄像头获取流地址
public class VideoService3 : VideoService2
{
    public override async Task<VideoPlayResultInfo> PlayVideo(VideoPlayInfo videoPlayInfo)
    {
        foreach (var camera in videoPlayInfo.Cameras)
        {
            // 1. 获取摄像头 IP 和凭证
            var info = await GetCameraInfoDic(camera.DeviceCode);

            // 2. 通过 ONVIF 协议直接连接摄像头
            var mediaClient = new MediaClient(
                BindingFactory.CreateSoapBinding(),
                new EndpointAddress($"http://{info.Ip}/onvif/media_service"));

            // 3. ONVIF 发现：获取 Profile → 获取 RTSP 流地址
            var profiles = await mediaClient.GetProfilesAsync();
            var streamUri = await mediaClient.GetStreamUriAsync(
                new GetStreamUri { ProfileToken = profiles[0].token, Protocol = "RTSP" });

            // 4. 注入凭证到 RTSP URL
            var rtspUrl = $"rtsp://{info.User}:{info.Password}@{streamUri.Uri}";
        }
    }
}
```

**策略选择**（`App.Service.cs`，DI 注册时根据配置决定）：

```csharp
// 这是 Context（上下文）角色——在启动时根据配置选择具体策略
switch (AddressConfigEnum.VideoMode.GetValue())
{
    case "1":
        containerRegistry.RegisterSingleton<IVideoService, VideoService>();    // ISCS 代理
        break;
    case "2":
        containerRegistry.RegisterSingleton<IVideoService, VideoService3>();   // ONVIF 直连
        break;
    default:
    case "0":
        containerRegistry.RegisterSingleton<IVideoService, VideoService2>();   // RTSP 直连
        break;
}
```

### 2.3 类继承关系

```
IVideoService (策略接口)
│
├── VideoService              ← 策略A: ISCS 代理播放
│   └── VideoService2         ← 策略B: RTSP 直连 + 宇视 PTZ（继承复用目录查询）
│       └── VideoService3     ← 策略C: ONVIF 直连（继承复用 RTSP 会话管理）
│
└── OfflineService.VideoService ← 装饰器（见装饰器模式章节）
```

### 2.4 优缺点

**优点：**
- 新增视频播放方案只需实现 `IVideoService`，不修改已有代码（开闭原则）
- 通过配置切换策略，无需修改业务代码
- 继承链设计合理：`VideoService2` 复用 `VideoService` 的目录查询，`VideoService3` 复用 `VideoService2` 的 PTZ 控制

**缺点：**
- 调用方需要知道不同策略的差异（通过配置值选择）
- 策略之间通过继承共享代码，耦合度高于组合方式

## 3. 装饰器模式（Decorator）

### 3.1 概念

**装饰器模式**动态地给一个对象添加额外的职责，而不改变其结构。装饰器和被装饰对象实现相同接口，装饰器持有被装饰对象的引用，可以选择性地增强、替换或透传方法调用。

```
          ┌──────────────────┐
          │ <<interface>>    │
          │   IService       │
          │  + GetData()     │
          └────────┬─────────┘
                   │ implements
       ┌───────────┴───────────┐
       │                       │
┌──────▼──────────┐   ┌───────▼──────────────┐
│ RealService     │   │ ServiceDecorator     │
│ (真实实现)      │   │  _inner: IService     │
│                 │   │  GetData():           │
└─────────────────┘   │    条件满足→返回缓存   │
                      │    否则→_inner.GetData│
                      └──────────────────────┘
                              ▲ wraps
                      ┌───────┴──────────────┐
                      │ RealService           │
                      └──────────────────────┘
```

### 3.2 项目中的实现：OfflineService 离线服务装饰器

项目为每个业务服务都提供了离线模式的装饰器，在不修改真实服务代码的前提下，添加离线数据支持。

**装饰器注册方式**（`App.Service.cs`，注释掉的 `RegisterMockService`）：

```csharp
// 真实模式：直接注册真实服务

// 离线模式：用装饰器包裹真实服务

        new DeviceService()));                        // 真实服务（被装饰者）
```

**离线数据源**（`MQService.ReadJson<T>`）：

```csharp
public static T ReadJson<T>(string tag, string command = null)
{
    // 从 exe 目录下的 Data\ 子目录读取预录制的 JSON 文件
    string fp = command == null
        ? AppDomain.CurrentDomain.BaseDirectory + $"Data\\{GetLocalFileName(tag)}.json"
        : AppDomain.CurrentDomain.BaseDirectory + $"Data\\{command}\\{tag}.json";

    if (!File.Exists(fp)) return default;
    return JsonConvert.DeserializeObject<T>(File.ReadAllText(fp));
}
```

### 3.3 装饰器的三种覆盖策略总结

| 策略 | 适用场景 | 示例 |
|------|---------|------|
| **透传** | 需要真实数据的读取操作 | `_deviceService.GetDeviceDetail()` |
| **存根** | 写操作/控制指令，返回假成功 | `new ResultInfo(true)` |
| **离线数据** | 可使用静态数据的读取操作 | `MQService.ReadJson<T>()` 从本地 JSON 读取 |

### 3.4 优缺点

**优点：**
- 不修改真实服务代码即可添加离线能力
- 可以在运行时通过配置开关切换真实/离线模式
- 装饰器可按需组合：未来可以叠加日志装饰器、缓存装饰器等

**缺点：**
- 需要为每个服务接口编写装饰器类（项目中有 30+ 个）
- 纯透传的装饰器代码冗余

## 4. 外观模式（Facade）

### 4.1 概念

**外观模式**为一个子系统中的一组接口提供一个统一的高层接口，使子系统更容易使用。客户端只需要调用外观类的简单方法，不需要了解子系统内部的复杂交互。

```
              ┌─────────────────────────────────────┐
              │           Facade (RestApi)           │
              │                                      │
 Client ─────►│  RequestAsync(url, params)           │
              │    └── 内部协调:                     │
              │         ├── RestSharp 发请求         │
              │         ├── OAuth Token 注入         │
              │         ├── 401 自动刷新 + 重试      │
              │         ├── JSON 反序列化            │
              │         └── 异常兜底                 │
              └─────────────────────────────────────┘
```

### 4.2 项目中的实现：RestApi 类

```csharp
// ═══ 核心请求方法（所有公开方法最终调用此方法）═══
internal static IRestResponse InnerRequest<T>(string url, T inputObject,
    Method method, IDictionary<string, string> paras, ...)
{
    // 1. 创建 RestSharp 请求对象
    var restRequest = new RestRequest(method)
    {
        RequestFormat = DataFormat.Json,
        JsonSerializer = new NewtonJsonSerializer(isContainPara, paras),
        Timeout = TimeOut == 0 ? timeOut : TimeOut * 1000
    };

    // 2. 注入认证信息
    restRequest.AddHeader("Timestamp", DateTime.Now.ToString("yyyyMMddHHmmss"));
    restRequest.AddHeader("ID-Token", OAuthResult?.AccessToken);

    // 3. 构建 OAuth2 认证器
    var header = new OAuth2AuthorizationRequestHeaderAuthenticator(Credential, "Basic");
    var restClient = new RestClient(url);
    restClient.Authenticator = header;
    header.Authenticate(restClient, restRequest);

    // 4. 执行请求
    return restClient.Execute(restRequest);
}
```

**Token 自动刷新 + 并发防抖（双重检查锁定）：**

```csharp
private static readonly object _Locker = new object();

private static RestfulResponse<K> ResponseHander<T, K>(...)
{
    var content = JsonConvert.DeserializeObject<RestfulResponse<K>>(responseStr);

    // 检测 401/403 → 自动刷新 Token → 重试
    if ((content.Code == 401 || content.Code == 403)
        && !string.IsNullOrWhiteSpace(OAuthResult?.RefreshToken))
    {
        var requestToken = OAuthResult.AccessToken;  // 记录当前 Token

        lock (_Locker)  // 并发保护
        {
            // 双重检查：等待锁期间可能被其他线程刷新了
            if (requestToken != OAuthResult.AccessToken)
            {
                // 其他线程已刷新完成，直接重试
            }
            else
            {
                // 执行 Token 刷新
                OAuthorizeByType(RefreshUrl, ..., OAuthorizeType.RefreshToken, ...);
            }
        }

        // 用新 Token 重试原请求（仅重试一次）
        content.Data = Request<K>(url, inputValue, method, ...);
    }

    return content;
}
```

### 4.3 封装的子系统一览

| 子系统 | 封装内容 | 调用者感知 |
|--------|---------|-----------|
| **RestSharp** | `RestClient`、`RestRequest`、`IRestResponse` | 调用者只看到 `RequestAsync<T>()` |

- 异常被吞掉可能导致问题难以定位
- `Task.Run` 包装同步调用不是真正的异步 I/O

## 5. 工厂模式（Factory Method）

### 5.1 概念

**工厂模式**定义一个创建对象的接口，让子类（或工厂方法）决定实例化哪个类。客户端不直接 `new` 具体类，而是通过工厂获取实例，将对象的创建和使用分离。

```
          Client
            │
            │ 使用工厂创建
            ▼
   ┌────────────────────┐
   │   Factory          │
   │  + Create(param)   │──► 根据参数决定创建哪种具体产品
   └────────┬───────────┘
            │ creates
   ┌────────▼───────────┐
   │ <<interface>>      │
   │   IProduct         │
   └────────┬───────────┘
            │ implements
     ┌──────┴──────┐
     │             │
┌────▼────┐  ┌────▼─────┐
│ProductA │  │ProductB  │
└─────────┘  └──────────┘
```

### 5.2 项目中的实现：ConnectionFactory（RocketMQ 消费者工厂）

- 工厂逻辑集中在一个类中，随产品种类增多会膨胀

## 6. 模板方法模式（Template Method）

### 6.1 概念

**模板方法模式**在父类中定义一个算法的骨架（模板），将某些步骤延迟到子类实现。子类可以不改变算法结构的情况下，重新定义算法的某些步骤。

```
   ┌──────────────────────────────────────┐
   │  AbstractClass (ViewModelBase)       │
   │                                      │
   │  + TemplateMethod():  ← 算法骨架     │
   │      Step1()  ← InitBaseData()      │
   │      if (IsActive)                   │
   │          Step2()  ← GetData()       │
   │                                      │
   │  # abstract GetData()  ← 子类实现    │
   │  # abstract InitBaseData()           │
   └──────────────────┬───────────────────┘
                      │ inherits
         ┌────────────┼────────────┐
         │            │            │
   ┌─────▼─────┐ ┌───▼──────┐ ┌──▼──────────┐
   │StationVM  │ │Emergency │ │DataBoard VM │
   │GetData(): │ │VM        │ │GetData():   │
   │ 请求车站  │ │GetData():│ │ 请求看板    │
   │ 数据      │ │ 请求应急  │ │ 数据        │
   │           │ │ 数据     │ │             │
   └───────────┘ └──────────┘ └─────────────┘
```

### 6.2 项目中的实现：ViewModel 基类链

项目设计了多层次的 ViewModel 基类，通过模板方法定义数据刷新的算法骨架。

**模板方法定义**（`Nuget\Hjmos\Common\ViewModelBase\ViewModelBase.cs`）：

```csharp
public abstract class ViewModelBase : ModelBase
{
    /// <summary>
    /// 构造时订阅全局更新事件
    /// </summary>
    public ViewModelBase(bool IsUpdateData)
    {
        if (IsUpdateData)
        {
            // ═══ 模板方法：定义算法骨架 ═══
            // 每日午夜 GlobalUpdate 事件触发时，按固定顺序执行：
            //   1. InitBaseData()  — 初始化基础数据（子类实现）
            //   2. if (IsActive) GetData()  — 仅在视图活跃时获取业务数据（子类实现）
            PrismService.EventBus.GetEvent(CommonEvents.GlobalUpdate).Subscribe(() =>
            {
                InitBaseData();                    // 步骤 1：基础数据初始化
                if (IsActive)
                    GetData();                     // 步骤 2：业务数据获取（仅活跃视图）
            }, ThreadOption.BackgroundThread, false);
        }
    }

    /// <summary>
    /// 获取业务数据 — 子类必须实现
    /// </summary>
    public abstract void GetData();

    /// <summary>
    /// 初始化基础数据 — 子类必须实现
    /// </summary>
    public abstract void InitBaseData();

    /// <summary>
    /// 初始化参数数据 — 子类可选覆盖
    /// </summary>
    public virtual void InitParamData() { }
}
```

**ActiveModelBase — 带生命周期的增强版**（`Nuget\Hjmos\Common\ViewModelBase\ActiveModelBase.cs`）：

```csharp
public abstract class ActiveModelBase : ModelBase, IUserControlStatus
{
    private bool _IsActive;

    /// <summary>
    /// 激活状态属性 — 状态变更时自动管理事件订阅
    /// </summary>
    public bool IsActive
    {
        get => _IsActive;
        set
        {
            if (SetProperty(ref _IsActive, value))
            {
                SetInfoRecevieStatus(value);  // ← 关键：根据状态订阅/取消订阅
            }
        }
    }

    /// <summary>
    /// 状态变更时自动管理 GlobalUpdate 事件订阅
    /// </summary>
    private void SetInfoRecevieStatus(bool status)
    {
        if (status)
        {
            // 视图激活 → 订阅全局更新
            PrismService.EventBus.GetEvent(CommonEvents.GlobalUpdate)
                .Subscribe(GlobalUpdate, ThreadOption.BackgroundThread, false);
        }
        else
        {
            // 视图隐藏 → 取消订阅（避免后台视图消耗资源）
            PrismService.EventBus.GetEvent(CommonEvents.GlobalUpdate)
                .Unsubscribe(GlobalUpdate);
        }
    }

    private void GlobalUpdate()
    {
        if (IsActive)
            GlobalUpdateEvent?.Invoke();  // 触发子类注册的更新逻辑
    }

    protected event Action<bool>? ActiveChanged;
    protected event Action? GlobalUpdateEvent;
}
```

```
BindableBase  (Prism)
  └── ModelBase  (+IDialogAware, +BeginInvoke)
       │
```

### 6.4 优缺点

- `IsActive` 检查避免后台视图无意义刷新，节省资源

- 基类链较深（4-5 层），理解成本较高

## 7. 适配器模式（Adapter）

### 7.1 概念

**适配器模式**将一个类的接口转换成客户端期望的另一个接口，使原本因接口不兼容而不能一起工作的类可以协同工作。

```
   Client                Adapter                 Adaptee
   ┌────────┐     ┌────────────────┐     ┌─────────────────┐
   │        │────►│ RegionService   │────►│ Prism            │
   │ShowView│     │ + ShowView()   │     │ IRegionManager   │
   │(简单)  │     │ + Deactivate() │     │ + RequestNavigate│
   └────────┘     │ + SendMsg()    │     │ + Add/Activate   │
                  └────────────────┘     │ + GetView        │
                                         └─────────────────┘
   调用者只看到                适配层封装了              底层复杂的
   简洁的 API                缓存/生命周期/广播          Prism Region API
```

### 7.2 项目中的实现：RegionService 适配 Prism IRegionManager

Prism 原生的 `IRegionManager.RequestNavigate()` 功能有限（不缓存视图、不支持子视图广播、不支持回调）。`RegionService` 对其进行了适配和增强。

```csharp
    public void SendMsgToChildren(object obj, IRegionParameters regionParameters = null)
    {
        // 递归遍历 WPF 可视化树
        // 找到所有 DataContext 实现 IRegionAware 的子控件
        // 调用 OnViewActived() 传递参数
    }
```

### 7.3 适配器增强对比

| 特性 | Prism 原生 IRegionManager | RegionService 适配后 |
|------|--------------------------|---------------------|
| 视图缓存 | ❌ 每次导航可能创建新实例 | ✅ 按 `FullName` 缓存，复用已有实例 |
| 生命周期通知 | `INavigationAware`（3 个方法） | `IRegionAware`（1 个方法 `OnViewActived`） |
| 父子通信 | ❌ 不支持 | ✅ `IRegionCallBackAware` + `SendMsgToChildren` |
| 强制刷新 | ❌ 不支持 | ✅ `isReload` 参数删除缓存重建 |

### 7.4 优缺点

**优点：**
- 视图复用显著提升切换速度（地铁管控平台视图含大量控件和 CefSharp 浏览器）
- 简化了 Prism Region 的使用复杂度
- 新增了子视图广播等 Prism 不提供的功能

**缺点：**
- 全局缓存可能导致内存泄漏（视图不再使用但仍被缓存）
- 封装过深可能掩盖 Prism 底层的有用功能

## 8. 单例模式（Singleton）

### 8.1 概念

**单例模式**确保一个类只有一个实例，并提供一个全局访问点。常用于管理共享资源（数据库连接池、配置管理器、浏览器引擎等）。

**双重检查锁定（Double-Check Locking）** 是线程安全单例的经典实现：
1. 第一次检查（无锁）：如果已初始化，直接返回（快速路径）
2. 加锁：只有未初始化时才进入锁
3. 第二次检查（锁内）：防止在锁等待期间被其他线程抢先初始化

```
   线程A ──► isInit? ──否──► lock ──► isInit? ──否──► Initialize()
                │                           │
               是                          是（线程B已初始化）
                │                           │
                ▼                           ▼
             return                      return
```

### 8.2 项目中的实现 A：CefBrowserTool（双重检查锁定）

CefSharp（Chromium 浏览器引擎）是**进程级单例**——一个进程只能初始化一次。多个 H5 面板可能同时创建 `HJBrowser` 控件，必须保证 `Cef.Initialize()` 只调用一次。

```csharp
public static class CefBrowserTool
{
    private static readonly object _lock = new object();

    public static void Init()
    {
        // ═══ 第一次检查：快速路径（无锁）═══
        // Cef.IsInitialized 是原子读，开销极低
        if (Cef.IsInitialized)
        {
            return;  // 已初始化，99% 的调用走这条路
        }

        // ═══ 加锁：仅在首次调用时进入 ═══
        lock (_lock)
        {
            // ═══ 第二次检查：防止锁等待期间被其他线程抢先 ═══
            if (Cef.IsInitialized)
            {
                return;  // 其他线程已完成初始化
            }

            // ═══ 实际初始化（只执行一次）═══
            var settings = new CefSettings();
            settings.Locale = "zh-CN";
            settings.LogSeverity = LogSeverity.Disable;
            settings.CefCommandLineArgs.Add("enable-gpu", "1");
            settings.CefCommandLineArgs.Add("proxy-auto-detect", "0");
            settings.CefCommandLineArgs.Add("no-proxy-serve", "1");

            var cachePath = Path.Combine(Directory.GetCurrentDirectory(), "cache");
            if (!Directory.Exists(cachePath)) Directory.CreateDirectory(cachePath);
            settings.CachePath = cachePath;

            CefSharpSettings.SubprocessExitIfParentProcessClosed = true;
            Cef.Initialize(settings, performDependencyCheck: false, browserProcessHandler: null);
        }
    }
}
```

### 8.3 项目中的实现 B：CacheHelper（静态单例包装）

`CacheHelper` 封装了 .NET 内置的 `MemoryCache.Default`（本身就是单例），提供类型安全的缓存访问。

```csharp
public static class CacheHelper
{
    // MemoryCache.Default 是 .NET 内置的进程级单例
    private static ObjectCache _Cache = MemoryCache.Default;

    /// <summary>
    /// 设置缓存（可选过期时间，单位：秒）
    /// </summary>
    public static void Set<T>(string name, T value, int? duration = null)
    {
        if (value == null) return;
        CacheItemPolicy policy = new CacheItemPolicy();
        if (duration != null)
            policy.AbsoluteExpiration = DateTime.Now.AddSeconds(Convert.ToDouble(duration));
        _Cache.Set(name, value, policy);
    }

    /// <summary>
    /// 获取缓存（不存在返回 default(T)）
    /// </summary>
    public static T Get<T>(string name)
    {
        if (Contains(name))
            return (T)_Cache[name];
        return default;
    }

    /// <summary>
    /// 缓存数据是否存在
    /// </summary>
    public static bool Contains(string name) => _Cache.Contains(name);
}
```

**使用示例**（基础数据缓存，避免重复网络请求）：

```csharp
// 首次获取：从 API 请求并缓存
public async Task<List<Station>> GetAllStations()
{
    var cached = CacheHelper.Get<List<Station>>("AllStations");
    if (cached != null) return cached;

    var result = await RestApi.RequestAsync<List<Station>>("/api/station/list");
    CacheHelper.Set("AllStations", result.Data, duration: 3600);  // 缓存 1 小时
    return result.Data;
}
```

### 8.5 三种单例实现方式对比

| 实现方式 | 类 | 线程安全 | 生命周期 | 可测试性 |
|---------|-----|---------|---------|---------|
| **双重检查锁定** | `CefBrowserTool` | ✅ lock + 双检 | 进程级 | ❌ 静态类不可 mock |
| **静态字段** | `CacheHelper` | ✅ MemoryCache 内部保证 | 进程级 | ❌ 静态类不可 mock |
| **DI 容器单例** | `IBasicDataService` 等 | ✅ 容器保证 | 容器级（应用生命周期） | ✅ 可替换为 mock |

### 8.6 优缺点

**优点：**
- CefSharp 初始化代价高（数百毫秒），单例避免重复初始化
- 缓存单例减少网络请求
- DI 单例提供了依赖注入的可测试性

**缺点：**
- 静态单例（CefBrowserTool、CacheHelper）不可 mock，难以单元测试
- 静态单例的生命周期不可控，与进程绑定

## 9. 命令模式（Command）

### 9.1 概念

**命令模式**将请求（用户操作）封装为对象，从而支持请求的排队、撤销、日志记录等功能。命令对象将"谁触发了操作"和"谁执行操作"解耦。

```
   Invoker (按钮)        Command (DelegateCommand)        Receiver (ViewModel 方法)
   ┌──────────┐          ┌─────────────────────┐          ┌──────────────────┐
   │ Button   │──绑定───►│ DelegateCommand      │──调用───►│ ExecuteSave()    │
   │ Click    │          │ + Execute()          │          │ 调用服务、更新UI │
   └──────────┘          │ + CanExecute()       │          └──────────────────┘
                         └─────────────────────┘
```

### 9.2 项目中的实现：DelegateCommand

项目使用 Prism 的 `DelegateCommand` 实现所有用户交互命令，并通过 XAML 绑定到 UI 控件。

**ViewModel 中定义命令：**

```csharp
public class DeviceConfigViewModel : ModelBase
{
    // ═══ 命令定义 ═══
    public DelegateCommand SaveCommand { get; }
    public DelegateCommand DeleteCommand { get; }
    public DelegateCommand<object> CameraClickCommand { get; }

    public DeviceConfigViewModel()
    {
        // 无参命令：直接绑定到执行方法
        SaveCommand = new DelegateCommand(ExecuteSave);

        // 带 CanExecute 的命令：按钮根据条件启用/禁用
        DeleteCommand = new DelegateCommand(ExecuteDelete, CanDelete);

        // 带参数的命令：XAML 传递 CommandParameter
        CameraClickCommand = new DelegateCommand<object>(ExecuteCameraClick);
    }

    // ═══ 命令执行逻辑 ═══
    private async void ExecuteSave()
    {
        var result = await PrismService.Resolve<IDeviceService>()
            .SaveDevice(CurrentDevice);
        if (result.Success)
        {
            MessageBox.Info("保存成功");
        }
    }

    private bool CanDelete()
    {
        // 只有选中了设备才允许删除
        return SelectedDevice != null;
    }

    private void ExecuteCameraClick(object cameraCode)
    {
        // cameraCode 由 XAML CommandParameter 传入
        PlayCamera(cameraCode.ToString());
    }
}
```

**XAML 中绑定命令：**

```xml
<!-- 按钮绑定 SaveCommand -->
<Button Content="保存"
        Command="{Binding SaveCommand}" />

<!-- 删除按钮：CanDelete 返回 false 时自动禁用 -->
<Button Content="删除"
        Command="{Binding DeleteCommand}" />

<!-- 摄像头按钮：CommandParameter 传递摄像头编码 -->
<Button Content="查看"
        Command="{Binding CameraClickCommand}"
        CommandParameter="{Binding CameraCode}" />
```

### 9.3 DelegateCommand 的三种用法

| 类型 | 构造方式 | XAML | 适用场景 |
|------|---------|------|---------|
| 无参 | `new DelegateCommand(Method)` | `Command="{Binding Cmd}"` | 简单操作（保存、刷新） |
| 带条件 | `new DelegateCommand(Method, CanMethod)` | 同上（按钮自动禁用） | 需要前置条件的操作 |
| 带参数 | `new DelegateCommand<T>(Method)` | `CommandParameter="{Binding X}"` | 列表项操作（传 ID 等） |

### 9.4 优缺点

**优点：**
- UI 和业务逻辑完全解耦：XAML 只绑定命令名，不关心实现
- `CanExecute` 自动管理按钮的启用/禁用状态
- 所有命令统一管理，便于添加日志、权限检查等横切关注点

**缺点：**
- `DelegateCommand` 的回调是 `Action`（非 `Task`），`async void` 方法的异常无法被 `await` 捕获
- 项目中命令执行逻辑复杂时，ViewModel 方法过长

## 10. 中介者模式（Mediator）

### 10.1 概念

**中介者模式**用一个中介对象来封装一系列对象之间的交互。中介者使各对象不需要显式地相互引用，从而使其耦合松散，而且可以独立地改变它们之间的交互。

```
   没有中介者（网状耦合）              有中介者（星型解耦）

   A ←──────→ B                    A ──→ Mediator ←── B
   ↑  ↖   ↗  ↑                    ↑       │         ↑
   │    ↖ ↗   │                    │       │         │
   C ←──────→ D                    C ──→ Mediator ──→ D
```

### 10.2 项目中的实现：EventBus + RegionService 双重中介

项目中模块间的通信不直接引用，而是通过两个中介者协调：

**中介者 1 — EventBus（数据/事件中介）：**

```
   StationModule                    EmergencyModule
   ┌─────────────────┐             ┌─────────────────────┐
   │ 发布应急事件     │             │ 订阅应急事件         │
   │ EventBus        │  EventBus   │ EventBus             │
   │ .Publish()      │────────────►│ .Subscribe()         │
   └─────────────────┘             └─────────────────────┘
          │                                 │
          │        两个模块互不引用          │
          │        只知道 EventBus          │
```

**中介者 2 — RegionService（视图/导航中介）：**

```csharp
// 模块 A 触发导航——不直接引用模块 B 的视图
PrismService.RegionService.ShowView(
    "MainContentRegion",           // 目标区域
    typeof(EmergencyView),         // 目标视图类型（通过 Type，不通过直接引用）
    new RegionParameters {         // 传递参数
        { "eventId", eventId },
        { "stationCode", stationCode }
    }
);
```

**双重中介的完整交互流程**（以"应急事件 → 视频联动"为例）：

```
   ┌─────────────────┐                    ┌─────────────────┐
   │ EmergencyModule  │                    │   CctvModule     │
   │ (应急指挥模块)    │                    │ (视频监控模块)    │
   │                  │                    │                  │
   │ 1. 发布应急事件  │                    │                  │
   │ EventBus.Publish │                    │                  │
   │ (EmergencyEvent) │                    │                  │
   └────────┬────────┘                    └────────┬─────────┘
            │                                      │
            │         ┌────────────────┐           │
            └────────►│  EventBus      │◄──────────┘
                      │  (中介者 1)    │ 2. 视频模块订阅
                      │                │    收到应急事件
                      └────────┬───────┘    自动弹出视频
                               │
                               │
                      ┌────────▼───────┐
                      │ RegionService  │ 3. 视频模块通过
                      │  (中介者 2)    │    Region 导航
                      │                │    显示视频视图
                      └────────────────┘
```

**实际代码流程：**

```csharp
// ═══ 步骤 1：应急模块发布事件 ═══
// EmergencyCommandV1Module 中的某个 ViewModel
PrismService.EventBus
    .GetEvent<EmergencyInfo>(CommonEvents.EmergencyEvent)
    .Publish(new EmergencyInfo { EventId = 123, StationCode = "S001" });

// ═══ 步骤 2：视频模块订阅并响应 ═══
// CctvModule 中的 ViewModel（在构造时订阅）
PrismService.EventBus
    .GetEvent<EmergencyInfo>(CommonEvents.EmergencyEvent)
    .Subscribe(emergency =>
    {
        // 获取该车站的摄像头列表
        var cameras = PrismService.Resolve<IVideoService>()
            .GetVideoByStation(emergency.StationCode);

        // 自动播放关联摄像头
        PrismService.Resolve<IVideoService>().PlayVideo(new VideoPlayInfo { ... });
    },
    ThreadOption.UIThread,  // 在 UI 线程执行（更新视频控件）
    keepSubscriberReferenceAlive: false  // 弱引用
    );

// ═══ 步骤 3：通过 RegionService 显示视频视图 ═══
// 视频模块通过 RegionService 导航到视频面板
PrismService.RegionService.ShowView(
    "VideoRegion",
    typeof(VideoPlayerView),
    new RegionParameters { { "cameras", cameraList } }
);
```

### 10.3 中介者模式 vs 观察者模式的区别

| 对比项 | 观察者模式 | 中介者模式 |
|--------|-----------|-----------|
| **关注点** | 一对多的事件通知 | 多对多的交互协调 |
| **通信方向** | 单向：发布者 → 订阅者 | 多向：多个模块通过中介者交互 |
| **项目体现** | EventBus 的 Publish/Subscribe | EventBus + RegionService 共同协调模块交互 |
| **新增参与者** | 新增订阅者不影响发布者 | 新增模块需要中介者支持新的交互类型 |

### 10.4 优缺点

**优点：**
- 模块间零引用：`EmergencyModule` 不引用 `CctvModule` 的程序集
- 独立部署：理论上可以单独替换某个模块的 DLL
- 集中管理交互逻辑：所有跨模块通信通过 EventBus 和 RegionService

**缺点：**
- 中介者本身可能变得复杂（EventBus 的事件键越来越多）
- 调试困难：难以追踪一个事件触发了哪些模块的响应
