## 二、WPF 与 XAML

### Q1：WPF 中 `DependencyProperty` 和普通的 CLR 属性有什么区别？项目中哪些地方用到了自定义依赖属性？

**答：**

| 对比 | CLR 属性 | DependencyProperty |
|------|---------|-------------------|
| 存储 | 实例字段（每个对象一份） | 属性系统字典（静态注册，按需分配） |
| 数据绑定 | 仅可作为 Source | 可同时作为 Source 和 Target |
| 默认值 | 需在构造函数赋值 | 注册时声明，支持值继承 |
| 动画 | 不支持 | 支持动画驱动 |
| 变更通知 | 需手动实现 INPC | 属性系统自动触发回调 |
| 值验证 | 需手动 | 可通过 `CoerceValueCallback` |

**项目中的实际使用（60+ 处注册）：**

```csharp
// HJBrowser.xaml.cs — 嵌入 CefSharp 浏览器
public static readonly DependencyProperty AddressProperty =
    DependencyProperty.Register(nameof(Address), typeof(string), typeof(HJBrowser),
        new PropertyMetadata(string.Empty, OnAddressChanged));

public static readonly DependencyProperty SendH5MsgProperty =
    DependencyProperty.Register(nameof(SendH5Msg), typeof(H5SendMsgModel), typeof(HJBrowser),
        new PropertyMetadata(null, OnSendH5MsgChanged));

// VideoPlayer2.cs — VLC 视频播放器
public static readonly DependencyProperty AddressProperty =
    DependencyProperty.Register(nameof(Address), typeof(string), typeof(VideoPlayer2),
        new PropertyMetadata(string.Empty, (o, args) => {
            player.MediaPlayer.Play(new Media(player.LibVlc, new Uri(path)));
        }));
```

**使用原则：** ViewModel 用 `INotifyPropertyChanged`（Prism 的 `SetProperty`），自定义控件用 `DependencyProperty`。

### Q2：WPF 的 Airspace 问题是什么？项目中是如何解决的？

**答：**

**Airspace 问题**：WPF 使用 `HwndHost` 嵌入 Win32/WinForms 内容时，嵌入的 HWND 窗口始终在 WPF 渲染层之上，导致：
- WPF 的 Popup、ToolTip、Adorner 无法覆盖在嵌入内容之上
- 嵌入内容与 WPF 元素无法正确层叠

**项目中的实际场景与解决方案：**

| 场景 | 嵌入内容 | 解决方式 |
|------|---------|---------|
| 3D 车站全景 | Unity3D 外部进程 | `WindowsFormsHost` + `WinApiHelper.SetParent()` 重父窗口 |
| CCTV 视频监控 | WinForms 控件 | `EmbedHwndHost : HwndHost` 嵌入，隔离 airspace |
| CefSharp 浏览器 | Chromium 渲染 | CefSharp 自行处理了 airspace（独立 HWND） |

```csharp
// EmbedHwndHost.cs — 将外部进程窗口嵌入 WPF
internal class EmbedHwndHost : HwndHost
{
    protected override HandleRef BuildWindowCore(HandleRef hwndParent)
    {
        appProc.Start();
        hwndHost = appProc.MainWindowHandle;
        // 修改窗口样式为 WS_CHILD，重设父窗口
        uint newStyle = oldStyle | WS_CHILD & ~WS_POPUP & ~WS_BORDER;
        WinApiHelper.SetWindowLong(hwndHost, GWL_STYLE, newStyle);
        WinApiHelper.SetParent(hwndHost, hwndParent.Handle);
        return new HandleRef(this, hwndHost);
    }
}
```

### Q6：Prism 的 Region 导航在项目中是如何封装的？Scoped Region 解决了什么问题？

**答：**

**封装的 RegionService：**

```csharp
public class RegionService : IRegionService
{
    public void ShowView(string regionName, Type viewType, IRegionParameters parameters = null)
    {
        var region = PrismService.RegionManager.Regions[regionName];
        object obj = region.GetView(viewType.FullName);
        if (obj == null)
        {
            obj = ContainerLocator.Container.Resolve(viewType);
            region.Add(obj, viewType.FullName);
        }
        region.Activate(obj);
        // 通知 ViewModel 已激活
        if (obj is FrameworkElement fe && fe.DataContext is IRegionAware aware)
            aware.OnNavigatedTo(parameters);
    }
}
```

**Scoped Region 解决的问题：**

Git 提交记录中有一条关键记录：
> *"曲线救国修复了弹窗下无法使用 region 的问题。prism 的 region 设计思想是一个 window 管理一系列 region，弹窗中的 region 应该拥有自己的 ScopeRegionManager"*

```csharp

public class DevicePopupViewModel : BindableBase, IDialogAware

    {
        // 创建 Scoped RegionManager — 弹窗内部的 Region 独立管理
        ScopeRegionManager = regionManager.CreateRegionManager();
    }
}
```

### Q7：项目中的事件总线是如何使用的？EventAggregator 和自定义 EventBus 有什么区别？

**答：**

项目同时使用了**两套事件系统**：

| 事件系统 | 类型 | 用途 |
|---------|------|------|
| `PrismService.EventAggregator` | Prism 原生 `IEventAggregator` | 强类型事件（`PubSubEvent<T>`） |
| `PrismService.EventBus` | 自定义 `IEventBus`（枚举 Key） | 动态事件、全局事件 |

```csharp
// 方式一：Prism 强类型事件（250+ 处使用）
PrismService.EventAggregator.GetEvent<OrgChartEvent>().Publish(node);
PrismService.EventAggregator.GetEvent<VideoCallEvent>().Subscribe(OnVideoCall);

// 方式二：自定义 EventBus（枚举 Key 索引）
PrismService.EventBus.GetEvent(CommonEvents.GlobalUpdate).Subscribe(() => GetData());
PrismService.EventBus.GetEvent(CommonEvents.EmergencyEvent).Publish(data);
```

**自定义 EventBus 实现：**

```csharp
public class EventBus : IEventBus
{
    private readonly Dictionary<Enum, EventBase> events = new();

    public PubSubEvent<T> GetEvent<T>(Enum key)
    {
        if (!events.ContainsKey(key))
            events[key] = new PubSubEvent<T>();
        return (PubSubEvent<T>)events[key];
    }
}
```

**跨模块通信示例（Git 记录中的防汛功能）：**

```
    ↓ EventBus 广播
```

### Q10：CefSharp 和 WebView2 有什么区别？项目中为什么两个都用了？

**答：**

| 对比 | CefSharp | WebView2 |
|------|----------|----------|
| 内核 | Chromium Embedded Framework | Microsoft Edge（Chromium） |
| 发布方式 | 自带 Chromium 二进制（~200MB） | 依赖系统 Evergreen Runtime |
| .NET 支持 | net472 成熟，net6 需 NETCore 变体 | 原生支持 net462+ 和 net6+ |
| 项目中的库 | `Hjmos.Browser` | `Hjmos.WebView2` |

**两个都用的原因：**
- **历史原因**：项目早期基于 .NET Framework 4.7.2，CefSharp 在 net472 上最成熟
- **演进方向**：随着项目迁移到 .NET 6，WebView2 是微软推荐方案
- **现状**：`Hjmos.Browser`（CefSharp）是主力（197+ 处使用），`Hjmos.WebView2` 用于新模块

## 六、WebSocket 实时通信

### Q11：项目中 WebSocket 的心跳和重连机制是如何实现的？

**答：**

基于 `WebSocketSharp` 封装的 `WebSocketClient`，具备心跳 + 自动重连：

```csharp
public class WebSocketClient : IWebSocketClient
{
    private WebSocketSharp.WebSocket _client;

    public WebSocketClient(string url, IDictionary<string, object> param,
        IDictionary<string, object> heartbeatParam = null,
        int heartbeatInternal = 295000)  // 默认 295 秒
    {
        Connect(url, heartbeatParam, heartbeatInternal);
        Send(param);  // 发送订阅参数
    }

    // 后台心跳线程
    Task.Factory.StartNew(() =>
    {
        while (!_isConnectionClosed)
        {
            if (_client.IsAlive)
            {
                Send(heartbeatParam);              // 发送心跳
                Task.Delay(heartbeatInternal).Wait(); // 等待 295 秒
            }
            else
            {
                _isConnectionClosed = !ReConnect(3); // 重连 3 次
            }
        }
    }, TaskCreationOptions.LongRunning);
}
```

**关键设计参数：**

| 参数 | 值 | 说明 |
|------|---|------|
| 心跳间隔 | 295 秒 | 略小于服务端/网关超时（300 秒） |
| 重连次数 | 3 次 | 超过后标记连接关闭 |
| 任务模式 | `LongRunning` | 专用线程，不占线程池 |

**使用场景（Git 记录）：**
- 开站/关站流程中的设备状态实时推送
- 应急指挥中的事件实时通知
- 防汛监测中的水位/雨量实时数据

## 八、HTTP 客户端（RestSharp + Refit）

### Q13：项目的 REST API 调用是如何封装的？OAuth2 Token 是怎么管理的？

**答：**

**集中式 HTTP 封装 — `RestApi`：**

```csharp
// RestApi.cs — 项目核心 HTTP 客户端
public static class RestApi
{
    public static OAuthResult OAuthResult { get; set; }  // 全局 Token

    // 带自动重试的 GET 请求
    public static T Request<T>(string url, Dictionary<string, object> param = null)
    {
        var client = new RestClient(BaseUrl);
        var request = new RestRequest(url, Method.GET);
        request.AddHeader("Authorization", $"Bearer {OAuthResult.AccessToken}");
        var response = client.Execute(request);
        return JsonConvert.DeserializeObject<RestfulResponse<T>>(response.Content).Data;
    }

    // 异步 POST 请求
    public static async Task<T> RequestAsync<T>(string url, object body) { ... }

    // 文件下载（带进度）
    public static async Task DownLoadWithProgress(string url, string savePath,
```

## 十二、进程管理（Job Object）

### Q18：Windows Job Object 在项目中的作用是什么？如何保证父子进程生命周期一致？

**答：**

**问题：** 主进程崩溃退出后，子进程可能变成孤儿进程，占用系统资源。

**解决方案：** 使用 Windows Job Object 将子进程绑定到主进程：

```csharp
public static class ChildProcessHelper
{
    private static IntPtr s_jobHandle;

    static ChildProcessHelper()
    {
        s_jobHandle = CreateJobObject(IntPtr.Zero, "HjmosJobObject");

        var info = new JOBOBJECT_BASIC_LIMIT_INFORMATION
        {
            // 关键标志：Job Object 关闭时自动杀死所有关联进程
            LimitFlags = JOBOBJECTLIMIT.JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE
        };

        SetInformationJobObject(s_jobHandle,
            JobObjectInfoType.ExtendedLimitInformation,
            ref info, Marshal.SizeOf<JOBOBJECT_BASIC_LIMIT_INFORMATION>());
    }

    // 将子进程加入 Job Object
    public static void AddChildProcess(Process process)
    {
        AssignProcessToJobObject(s_jobHandle, process.Handle);
    }

    // P/Invoke 声明
    [DllImport("kernel32.dll")]
    static extern IntPtr CreateJobObject(IntPtr lpAttr, string name);

    [DllImport("kernel32.dll")]
    static extern bool SetInformationJobObject(IntPtr hJob, JobObjectInfoType type,
        ref JOBOBJECT_BASIC_LIMIT_INFORMATION info, int size);

    [DllImport("kernel32.dll")]
    static extern bool AssignProcessToJobObject(IntPtr hJob, IntPtr hProcess);
}
```

**效果：** 主进程退出 → Job Object 句柄关闭 → OS 自动终止所有子进程，无孤儿进程。

### Q19：项目中的密码加密和 Token 安全是如何实现的？

**答：**

**加密体系：**

| 算法 | 实现类 | 用途 |
|------|--------|------|
| SHA256 | `SHAHelper` | 登录密码哈希 |
| MD5 | `MD5HashHelper` | 数据完整性校验 |
| AES | `AesHelper` | 敏感数据对称加密（配置文件中的密码） |
| RSA | `RSAHelper` | 密钥交换、数字签名 |

```csharp
// SHA256 密码哈希
public static string SHA256Encrypt(string input)
{
    using var sha256 = SHA256.Create();
    var bytes = sha256.ComputeHash(Encoding.UTF8.GetBytes(input));
    return BitConverter.ToString(bytes).Replace("-", "").ToLower();
}

// AES 加密 — IV 拼接在密文前
public static string Encrypt(string plainText, string key)
{
    using var aes = Aes.Create();
    aes.Key = Encoding.UTF8.GetBytes(key);
    aes.GenerateIV();
    using var encryptor = aes.CreateEncryptor();
    using var ms = new MemoryStream();
    ms.Write(aes.IV, 0, aes.IV.Length);  // 先写 IV
    using var cs = new CryptoStream(ms, encryptor, CryptoStreamMode.Write);
    var plainBytes = Encoding.UTF8.GetBytes(plainText);
    cs.Write(plainBytes, 0, plainBytes.Length);
    cs.FlushFinalBlock();
    return Convert.ToBase64String(ms.ToArray());
}
```

```
子进程崩溃
    │
    ├── 方式一：Process.Exited 事件（ExitCode ≠ 0）
    │     → 保存 PendingModuleRestore = AssignedModule
    │     → 2 秒后 AutoRestartWorkerAsync
    │     → 新进程预热 → Ready → 检测 PendingModuleRestore
    │     → 自动发送 ActivateModule → 恢复窗口
    │
    ├── 方式二：命名管道断开（Disconnected 事件）
    │     → HandleServerReconnectAsync
    │     → 创建新 Server 管道 → 等待 Worker 重连
    │     → 指数退避（500ms → 1s → 2s → ... → 10s）
    │
    └── 方式三：Job Object 兜底
          → 主进程退出 → 所有子进程自动终止
          → 不会出现孤儿进程
```

### Q30：项目中如何保证模块间的松耦合？

**答：**

**五层解耦策略：**

| 层次 | 机制 | 示例 |
|------|------|------|
| **类型解耦** | 接口定义在 `Common`，实现在各自模块 | `IDataService` 接口公共，`DataService` 在 TempService |
| **导航解耦** | Region 导航通过字符串名称 | `ShowView("StationRegion", viewType)` |
| **事件解耦** | EventAggregator 发布-订阅 | 应急模块发布事件，CCTV/看板/防汛各自响应 |
| **DI 解耦** | 容器注册接口-实现映射 | `RegisterSingleton<IBasicDataService, BasicDataService>()` |
| **进程解耦** | 命名管道 IPC + 服务代理 | 子进程通过 `ServiceProxy` 透明调用主进程服务 |

**核心原则：** 模块之间**零直接引用**，全部通过 `Hjmos.Ncc.Common` 中的接口/事件/枚举间接关联。
