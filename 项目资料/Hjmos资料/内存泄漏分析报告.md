### 1. RegionService 视图永久缓存 — 所有视图只增不删

**文件:** `Nuget/Nuget/Hjmos.Common/Services/RegionService.cs`

**问题描述:**

`ShowView()` 方法在首次调用时将视图 `Add()` 到 Region，之后只调用 `Activate()`，**从不调用 `Remove()`**。虽然 `DeleteView()` 方法存在，但整个项目中**从未被任何模块调用过**。

```csharp
// RegionService.cs 第50-72行
public void ShowView(string regionName, Type viewType)
{
    var region = PrismService.RegionManager.Regions[regionName];
    string fullName = viewType.FullName;
    object obj = region.GetView(fullName);
    if (obj == null)
    {
        obj = ContainerLocator.Container.Resolve(viewType);
        region.Add(obj, fullName);       // ← 添加后永远不会移除
    }
    region.Activate(obj);                // ← 只是激活，旧视图仍在内存中
}
```

**影响:**

- 每个模块的每个视图首次加载后**永久驻留内存**
- 视图关联的 ViewModel、数据集合、图表、定时器、WebSocket 连接全部保留不释放
- 在各模块间切换时（如 全景 ↔ 应急指挥 ↔ 视频监控），旧模块的视图不会释放
- 随着用户操作，内存只增不减

**修复建议:**

- 方案A：在 `ShowView()` 中切换视图时，先对当前激活的旧视图调用 `region.Remove()`，再添加/激活新视图
- 方案B：为 `IRegionAware` 接口增加 `OnViewDeactived()` 回调，在视图被切换走时让 ViewModel 清理资源（停止定时器、关闭 WebSocket、取消订阅等）
- 方案C：增加 LRU 驱逐策略，保留最近 N 个视图，移除最久未访问的视图

### 2. WebSocketClient 未实现 IDisposable — 后台线程永久泄漏

**文件:** `Nuget/Nuget/Hjmos.WebSocket/WebSocketClient.cs`

**问题描述:**

构造函数中通过 `Task.Factory.StartNew(..., TaskCreationOptions.LongRunning)` 创建了**永久后台线程**（第86行），该线程运行心跳循环：

```csharp
// WebSocketClient.cs 第86-114行
Task.Factory.StartNew(() =>
{
    while (!_isConnectionClosed)      // ← 只有 Close() 才会设为 true
    {
        if (_client.IsAlive)
        {
            if (heartbeatParam != null) Send(heartbeatParam);
            Task.Delay(heartbeatInternal).Wait();  // ← 阻塞线程，默认295秒
        }
        else
        {
            _isConnectionClosed = !ReConnect(3);   // ← 重连失败才退出
        }
    }
}, TaskCreationOptions.LongRunning);
```

具体问题：
- **未实现 `IDisposable`** — 调用者必须手动记住调用 `Close()`，否则线程永远运行
- `Close()` 方法仅调用 `CloseAsync()` 并设置标志位，**不取消事件订阅**（`OnOpen/OnClose/OnError/OnMessage`）
- `Task.Delay(heartbeatInternal).Wait()` 阻塞线程，默认心跳间隔 295 秒，即使调用 Close 也需等待当前 Delay 结束
- `ReConnect()` 在已失败的连接上直接调用 `Connect()` 而不先关闭旧连接

**受影响的 ViewModel（12+个）:**

| 文件 | WebSocket 实例 | 是否有清理逻辑 |
|------|---------------|---------------|
| `MainInformationViewModel.cs` | `_WebSocketClient` + `_WebSocketClient1` | 部分（Close 但未 Dispose） |
| `IntelligentLinkageHelper.cs` | `_WebSocketClient` | ❌ 无 |
| `HandlingProcessViewModel.cs` | `_wsClient` | ❌ 无 |
| `CloseStationNightViewModel.cs` | `WsClient` | 部分 |
| `OpenStationMorningViewModel.cs` | `WsClient` | 部分 |
| `EscalatorControlViewModel.cs` | `WsClient` | ❌ 无 |
| `RollingShutterDoorControlViewModel.cs` | `WsClient` | ❌ 无 |
| `VerticalLadderControlViewModel.cs` | `WsClient` | ❌ 无 |
| `CircuitViewModel.cs` | `_wsClient` | ❌ 无 |
| `EveningHelperViewModel.cs` | `WsClient` | 部分 |

**修复建议:**

```csharp
public class WebSocketClient : IWebSocketClient, IDisposable
{
    private CancellationTokenSource _cts;
    
    // 在 Connect() 中用 CancellationToken 替代 _isConnectionClosed 标志
    // 在 Dispose() 中: _cts.Cancel(); _client.Close(); 取消事件订阅
    
    public void Dispose()
    {
        _cts?.Cancel();
        _client?.Close();
        _client.OnOpen -= Client_OnOpen;
        _client.OnClose -= Client_OnClose;
        _client.OnError -= Client_OnError;
        _client.OnMessage -= Client_OnMessage;
    }
}
```

### 3. RestFactory 每次调用创建新 HttpClient — Socket 耗尽

**文件:** `Nuget/Nuget/Hjmos.Rest/Factory/RestFactory.cs`（第30行）

**问题描述:**

```csharp
// RestFactory.cs 第28-51行
public T Create<T>(string url, string token, string credential, ...)
{
    var client = new HttpClient(                    // ← 每次调用都创建新的
        new ResponseHandler(
            new HttpClientHandler(),                // ← 每次都打开新的 TCP 连接
            tryTimes, interval))
    {
        BaseAddress = new Uri(url),
        Timeout = TimeSpan.FromMilliseconds(timeOut)
    };
    // ...
    return RestService.For<T>(client, ...);
}
```

这是 .NET 中**最著名的反模式之一**：

- 每个 `HttpClientHandler` 打开独立的 TCP 连接池
- 连接在 GC + Finalizer 回收前不会释放（通常需要几分钟甚至更久）
- 高频 API 调用会导致 **socket 端口耗尽**（大量连接处于 `TIME_WAIT` 状态）
- 大量未释放的 socket 占用 Windows 内核内存（非托管内存），**不会被 GC 回收**

**修复建议:**

```csharp
public class RestFactory : IRestFactory
{
    // 按 BaseAddress 缓存 HttpClient
    private static readonly ConcurrentDictionary<string, HttpClient> _clientCache = new();
    
    public T Create<T>(string url, string token, ...)
    {
        var client = _clientCache.GetOrAdd(url, key => 
            new HttpClient(new ResponseHandler(new HttpClientHandler(), tryTimes, interval))
            {
                BaseAddress = new Uri(key),
                Timeout = TimeSpan.FromMilliseconds(timeOut)
            });
        // 设置请求头...
        return RestService.For<T>(client, ...);
    }
}
```

### 4. CefSharp 浏览器实例泄漏

**文件:** `Nuget/Nuget/Hjmos.Browser/HJBrowser.xaml.cs`

**问题描述:**

**问题 4a — KeepAlive 默认 true 导致浏览器不释放:**

```csharp
// HJBrowser.xaml.cs 第218-219行
public static readonly DependencyProperty KeepAliveProperty =
    DependencyProperty.Register("KeepAlive", typeof(bool), typeof(HJBrowser), 
        new PropertyMetadata(true));  // ← 默认为 true
```

```csharp
// HJBrowser.xaml.cs 第34-41行
private void HJBrowser_Unloaded(object sender, RoutedEventArgs e)
{
    Loaded -= CustomCefSharp_Loaded;
    if(!KeepAlive)              // ← KeepAlive=true 时不会执行 Dispose
    {
        this.CefSharp?.Dispose();
    }            
}
```

每个 CefSharp 实例对应一个独立的 **Chromium 子进程**，占用几十到上百 MB 内存。`KeepAlive` 默认为 `true` 意味着视图卸载时浏览器进程不会释放。

**问题 4b — Window.Closing 事件未取消订阅:**

```csharp
// HJBrowser.xaml.cs 第53-58行
Window.GetWindow(this).Closing -= CefSharpClosing;
Window.GetWindow(this).Closing += CefSharpClosing;  // ← 订阅后从未取消
```

Window 持有对浏览器控件的强引用，阻止 GC 回收。

**问题 4c — 重复创建浏览器实例:**

```csharp
// HJBrowser.xaml.cs 第121-149行
private void InitCefSharp()
{
    CefSharp = new ChromiumWebBrowser();  // ← 每次 Loaded 创建新实例
    // 旧的实例如果没有被 Dispose 就泄漏了
}
```

**修复建议:**

- 将 `KeepAlive` 默认值改为 `false`
- 在 `HJBrowser_Unloaded` 中增加 `Window.GetWindow(this).Closing -= CefSharpClosing;`
- 在 `InitCefSharp()` 开头先 `CefSharp?.Dispose()` 清理旧实例

### 5. MQ (RocketMQ) SWIG 原生对象未 Dispose

**文件:** `Nuget/Nuget/Hjmos.MQProxy/Client/ConsumerMQ.cs`

**问题描述:**

MQ SDK 类（`PushConsumer`、`Message`、`ONSFactory` 等）是 **SWIG 生成的 C++ 包装器**，持有非托管内存。但 `Stop()` 方法仅调用 `shutdown()` 而不调用 `Dispose()`：

```csharp
// ConsumerMQ.cs 第182-185行
public void Stop()
{
    _consumer?.shutdown();    // ← 仅 shutdown，未 Dispose
    // 缺少: _consumer?.Dispose();
    // 缺少: _listener?.Dispose();
}
```

```csharp
// PushConsumerMQ.cs 第278-281行
public void Stop()
{
    _consumer?.shutdown();    // ← 同样的问题
}
```

`MyMsgListener` 的析构函数为空，无法释放原生资源：

```csharp
// ConsumerMQ.cs 第21-23行
~MyMsgListener()
{
    // ← 空实现，应调用 base.Dispose() 或原生清理
}
```

此外，`App.Service.cs` 中注册的单例 `IConsumer` 在应用退出时从未被 Stop/Dispose。

**修复建议:**

```csharp
public void Stop()
{
    _consumer?.shutdown();
    _consumer?.Dispose();     // 释放 SWIG 原生资源
    _listener?.Dispose();     // 释放监听器原生资源
}
```

## P1 重要问题（应尽快修复）

### 6. SpinWait.SpinUntil 忙等待 — 阻塞线程池线程

**文件:**
- `Modules/Hjmos.Ncc.IntelligentLinkage/Helper/IntelligentLinkageHelper.cs`（第185、226行）
- `src/Hjmos.Shell/ViewModels/MainInformationViewModel.cs`（第225行）

**问题描述:**

在 `Task.Run` 的线程池线程中使用 `SpinWait.SpinUntil()` 忙等待弹窗关闭：

```csharp
// IntelligentLinkageHelper.cs 第178-185行
Application.Current.Dispatcher.Invoke(() =>
{
    PrismService.DialogService.Show(nameof(FloodPreventionEventView), parameter, p =>
    {
        isEnd = true;
    });
});
SpinWait.SpinUntil(() => isEnd);  // ← 忙等待，100% CPU 占用
```

- 如果多个联动事件排队，多个线程池线程被消耗在忙等待中
- `MainInformationViewModel.cs` 第225行在 `while` 循环中使用 `SpinWait.SpinUntil`，即使空闲也持续消耗 CPU

**修复建议:**

使用 `TaskCompletionSource<bool>` 替代忙等待：

```csharp
var tcs = new TaskCompletionSource<bool>();
Application.Current.Dispatcher.Invoke(() =>
{
    PrismService.DialogService.Show(name, parameter, p =>
    {
        tcs.TrySetResult(true);
    });
});
await tcs.Task;  // ← 异步等待，不占用 CPU
```

### 7. EventBus 订阅泄漏 — Subscribe 后从未 Unsubscribe

**问题描述:**

多个 ViewModel 在构造函数或方法中调用 `PrismService.EventBus.GetEvent<T>().Subscribe()`，但没有对应的 `Unsubscribe()`。EventAggregator 持有对 ViewModel 的强引用，导致 ViewModel 及其所有数据永远无法被 GC 回收。

**涉及文件:**

| 文件 | 问题 |
|------|------|
| `AnalysisContentViewModel.cs`（第321-324行） | 构造函数中 2 个 Subscribe，无 Unsubscribe |
| `StationPassengerEarlyWarningViewModel.cs`（第74行） | `GetData()` 可被多次调用，每次调用都 Subscribe，造成重复订阅 |
| `StationRealTimeVideoPlayTimesOfLast7DaysViewModel.cs`（第171行） | Unsubscribe 依赖 `ActiveChanged(false)` 触发，若视图被直接移除则不会执行 |
| `StationCameraStatisticsViewModel.cs`（第256行） | 同上 |
| `LineFloodPreventionWholeViewModel.cs`（第59行） | 同上 |
| 其他 10+ 个 ViewModel | 类似模式 |

**修复建议:**

- 为 ViewModel 基类 `ModelBase` 实现 Prism 的 `IDestructible` 接口
- 在 `Destroy()` 方法中统一取消所有 EventBus 订阅
- 在 `RegionService.ShowView()` 中切换视图时，对旧视图调用 `Destroy()`

### 9. PropertyChanged 匿名事件订阅无法取消

| `IndicatorEditView.xaml.cs` | 58 |
| `TrainOperationMonitorView.xaml.cs` | 31 |
| `EventLocationView.xaml.cs`（IntelligentLinkage） | 38 |
| `EventLocationView.xaml.cs`（StationEmergencyCommand） | 49 |
| `AddressBookMenuViewModel.cs`（自订阅 PropertyChanged） | 95 |
| `ReportMenuViewModel.cs`（自订阅 PropertyChanged） | 399 |
| `VideoCommunicationMenuViewModel.cs`（自订阅 PropertyChanged） | 91 |
| `TableDetailView.xaml.cs`（RegionContext.PropertyChanged） | 14 |

    }

或使用 `WeakEventManager` 进行弱事件订阅。

### 10. 静态集合无限增长

**问题描述:**

多个静态字典/列表只增不减，随着应用运行时间增长，占用内存持续增加。

| 文件 | 集合 | 问题 |
|------|------|------|

| `Growl.cs`（第58行） | `static Dictionary<string, Panel> PanelDic` | 同上 |
| `FluidMoveBehaviorBase.cs`（第30行） | `static Dictionary<object, TagData> TagDictionary` | 无任何清理机制 |
| `HotkeyHelper.cs`（第30行） | `static List<HotkeyMapping> _KeyMappings` | 无上限，无注销机制 |

| `GridHelper.cs`（第200行） | `static List<RecordGridRowCol> lstRowCol` | 只增不减 |
